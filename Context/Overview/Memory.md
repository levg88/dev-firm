## Facts
- Dev Firm is a local-first boutique software development firm run by agents; it takes an application brief through PM → architect → team lead → developers → tech lead → QA and produces a working, tested local app. (General)
- The team has seven roles: Product Manager (spec + task breakdown), Architect (design + file plan), Team Lead (design review, routing, bug triage), Backend and Frontend Developers, Tech Lead (code review), and QA (verification + bugs). (General)
- The codebase is TypeScript on Node.js 20+, Express 5, EJS views, SQLite via better-sqlite3, and Zod contracts between roles. (General)
- Top-level layout: `src/` is application source; `src/agents/` the agent runtime and role wrappers; `agents/` the Markdown agent definitions; `src/llm/` provider adapters; `src/orchestrator/` the delivery workflow; `src/tracker/` the local and GitHub ticket mirrors; `src/api/` Express routes; `views/` EJS templates; `tests/` Vitest suites. (General)
- Runtime data lives under `data/` (ignored by git): `dev.db`, per-run workspaces, storage, and artifacts. (General)
- The knowledge in this base covers agent roles, the delivery pipeline, LLM providers, ticket tracking, the workspace sandbox, local SQLite storage, setup and CLI operations. (General)
- The project is MIT licensed. (General)

## Gotchas
- Offline/mock mode is a placeholder pipeline: it records artifacts but does not write real code. Choose a real provider for the full team. (General)
- The local SQLite ticket board is the source of truth; GitHub sync is best-effort and a sync failure is recorded as a warning, never a build failure. (General)
- The workspace tools reject path escapes and restrict commands, but they are an isolation convenience, not a hardened security boundary. (General)
- Agent prompts are Markdown files under `agents/` loaded at runtime; editing TypeScript prompts is no longer how behaviour changes. (General)
- `data/` is gitignored. Do not commit `dev.db`, run workspaces, or generated artifacts. (General)
